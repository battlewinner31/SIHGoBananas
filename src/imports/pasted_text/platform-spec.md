## CORE PURPOSE

The platform connects government departments that have real-world challenges with startups that offer innovative solutions.

The basic journey is:

Government Challenge → Startup Solutions → Evaluation → Pilot → Scale

For this version, focus ONLY on the website structure and user experience. Do NOT add or simulate AI features, AI scores, chatbots, voice assistants, risk scores, readiness scores, or KPI analytics yet.

## IMPORTANT DESIGN AND DEVELOPMENT RULES

1. Preserve the existing website's visual identity wherever possible.
2. Do not unnecessarily redesign existing components.
3. Reuse existing buttons, cards, navigation, typography, spacing, and layouts.
4. Keep the website professional, minimal, trustworthy, and suitable for a government platform.
5. Avoid excessive animations, gradients, decorative effects, or flashy "AI startup" visuals.
6. Do not create separate hard-coded pages for individual startups or challenges. Use reusable templates/components.
7. Keep the number of pages/screens minimal.
8. Challenges and Solutions should be public browsing sections.
9. After login, Government should have ONE dashboard and Startup should have ONE dashboard.
10. Do not implement AI functionality yet. The AI, readiness/risk assessment, chatbot, pilot tracking, KPI monitoring, validation, and scale recommendation features will be added later.
11. Use realistic placeholder/sample data so the prototype looks like a functioning platform.
12. Make all navigation links and buttons work between the relevant screens.
13. Maintain a consistent responsive layout suitable for desktop and mobile.
14. Make the final website feel like ONE coherent platform, not a collection of unrelated template pages.

The goal is a clean, functional base prototype that visually demonstrates the complete government-to-startup journey without implementing the AI features yet.
